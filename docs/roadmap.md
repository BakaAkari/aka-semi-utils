# Roadmap / 开发路线图

本文件记录 `aka-semi-utils / 极简水印` 的长期方向、阶段拆分和当前开发优先级。任何较大的功能开发都应先更新本文件或对应阶段设计文档，再进入代码实现。

## 项目目标

`aka-semi-utils / 极简水印` 已转向公开 Web 图片水印工具。桌面版冻结在
`v2.1.9`，完整源码与发布历史保存在 `archive/desktop-v2` 分支；`main` 后续只推进
Web 产品、共享图片处理核心与服务端部署。

- 让普通摄影用户能稳定、直观地批量添加 EXIF 信息水印、品牌 Logo 和签名水印。
- 让配置系统可理解、可保存、可迁移、可恢复。
- 让预览、批处理、错误反馈和 Release 包具备可用的产品质量。
- 让每个重要功能阶段都有文档、版本、提交和验证记录，保证开发过程可追溯。

## 开发原则

1. **先文档后实现**：新功能或大改动必须先形成目标、范围、验收标准。
2. **小步可验证**：每个阶段尽量拆成可测试、可提交的小闭环。
3. **用户体验优先**：GUI 文案、默认值、错误提示和恢复能力优先面向普通用户。
4. **状态单一来源**：GUI 配置状态以 `AppState` 为核心，不在多个模块分散维护真相。
5. **Release 干净可复现**：发布包不包含开发者本机路径、私人签名或私人 Logo。

## 当前状态概览

- 桌面最终版：`v2.1.9`（归档分支 `archive/desktop-v2`）。
- Web 当前阶段：`0.1.0` 公测前安全加固。
- 当前主线：React/Vite 前端、FastAPI API、共享图片处理核心和腾讯云部署。
- 发布门槛：严格输入校验、无服务端模板注入、无任意路径读取、有界并发、文件自动过期、HTTPS 与限流。

## 阶段路线

### Archived：桌面 GUI Phase 6–10

状态：已冻结，不再进入 Web 主线开发；历史设计仅供归档查阅。

参考文档：`docs/phase6_design.md`

目标：

- 完善配置持久化。
- 统一字段定义。
- 改善四角布局编辑体验。
- 引入实时预览。
- 强化 JSON 模板与 GUI 状态同步。

后续整理要求：

- 将设计阶段 TODO 与实际已完成代码状态对齐。
- 对未完成项拆分为新的 Phase 或 Backlog。
- 避免历史设计文档被误读为当前待办清单。

### Phase 7：可用性与产品化打磨

状态：计划中。

目标：

- 梳理 GUI 全流程：导入图片、选择模板、调整水印、预览、批处理、查看错误。
- 优化默认配置、空状态、错误状态和恢复默认能力。
- 明确模板管理、用户配置、release 默认配置之间的边界。
- 增强用户手动测试清单。

候选任务：

- 配置面板信息架构整理。
- 预览失败时的非阻塞错误提示。
- 批处理结果汇总和失败详情优化。
- 默认模板与示例模板的说明整理。
- 新手第一次打开应用的引导体验。

验收方向：

- 用户可在不读代码的情况下完成一次批量加水印。
- 关闭并重启后，用户配置可预期恢复。
- 常见错误能以中文清楚提示。

### Phase 8：模板与配置生态

状态：计划中。

目标：

- 让模板、预设、用户配置具备清晰的导入、导出、恢复和迁移能力。
- 为后续更多水印风格和用户分享模板打基础。

候选任务：

- 模板文件结构和 schema 文档化。
- GUI 导入/导出模板。
- 预设管理。
- 用户配置迁移版本号。
- 模板兼容性测试。

### Phase 9：处理管线稳定性与性能

状态：计划中。

目标：

- 提升大批量图片处理时的稳定性、错误隔离和性能。
- 保证预览、单图处理、批处理行为一致。

候选任务：

- 批处理并发策略调优。
- EXIF 读取缓存与失败降级。
- HEIF/JPEG/PNG 等格式兼容性验证。
- 输出覆盖、命名冲突、异常恢复策略。
- 性能基准测试文档化。

### Phase 10：Release 与用户分发质量

状态：持续改进。

目标：

- 保证 Windows、macOS、Linux Release 包开箱可用。
- 发布流程可复现、可监控、可回滚。

候选任务：

- Release 包冒烟测试增强。
- exiftool 打包策略验证。
- macOS 安全提示说明。
- Release notes 标准化。
- 发布后资产校验自动化。

## Backlog / 待评估事项

以下事项暂不进入具体 Phase，需等需求明确后再设计：

- 多语言 GUI。
- 所见即所得模板编辑器。
- 撤销/重做。
- 多模板批量应用。
- 用户自定义品牌 Logo 库。
- 更完整的水印样式市场或模板分享机制。

## 每个阶段的完成定义

一个阶段只有在满足以下条件后才能视为完成：

1. roadmap 或阶段设计文档已更新。
2. 需求范围、非目标、验收标准已明确。
3. 代码实现完成并通过相关自动化测试。
4. 用户完成真实 GUI 功能测试，关键 bug 已修复。
5. README、版本号、Agent 规则或 Release notes 已按需同步。
6. 变更已形成清晰 commit；正式发布时已创建 tag 和 Release。
